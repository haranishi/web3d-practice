# Web 3D表現の実装練習

Three.jsを使い、Webサイト向けシェーダー表現とブラウザ3Dゲームを小さな完成品として試す学習リポジトリです。ビルド環境や3Dモデルに頼らず、1枚のHTMLから描画・操作・演出の原則を確認できます。

## 目的と背景

外部のObsidianノートに整理したWeb 3D・ゲーム制作の知識を、写経ではなく「動く作例」に落とすための練習です。

各サブディレクトリは独立した作例で、固有の学習内容、改造課題、操作方法はそれぞれのREADMEに残しています。このREADMEはリポジトリ全体の位置付けと共通制約だけを説明します。

## 収録している作例

### 01：シェーダーグラデーションのヒーロー

自作GLSLのsimplex noise、fbm、cosine paletteを組み合わせた、動くメッシュグラデーションのWebヒーローです。

マウスへの慣性追従、粒状感、ビネット、色空間とトーンマッピング、`prefers-reduced-motion` 対応を、モデルなしの全画面表現として検証しています。

### 02：玉転がしコイン収集ゲーム

ローポリのボールで12枚のコインを集めるタイムアタックです。キーボードとタッチ操作、追従カメラ、効果音、パーティクル、ベストタイム保存までを1ファイルに収めています。

物理エンジンを最初から導入せず、高さマップによる着地と円対箱の横衝突を自作しています。これは物理処理の役割を一度自分で実装して理解する、という学習上の判断です。

## 共通の設計判断

- 各作例は `index.html` だけで完結させ、npmやバンドラーを必要としない
- Three.jsはimport mapからunpkg上の `0.160.0` を読み込む
- 外部3Dモデル、画像、音源を置かず、形状・シェーダー・Web Audioで表現する
- 画面更新はデルタタイム基準とし、高リフレッシュレートで速度が変わらないようにする
- 動きを減らすOS設定を尊重し、過剰なシェイクやパーティクルを抑える

## 動作条件

WebGLとES Modulesに対応したブラウザ、およびCDNへ接続できるネットワークが必要です。各 `index.html` は直接開けますが、CDN障害やThree.js配信仕様の変更には影響を受けます。

```bash
python3 -m http.server 8080
```

ローカルサーバーを使う場合はリポジトリ直下で実行し、各サブディレクトリへアクセスします。

## 制約と落とし穴

- Three.jsのバージョンを変えると、シェーダー、色管理、import mapの互換性確認が必要
- ゲームのベストタイムはブラウザの`localStorage`だけに保存され、端末間では同期されない
- 音はブラウザの自動再生制限に従い、最初のユーザー入力後に有効になる
- 自作物理は学習用であり、複雑な形状、連続衝突、厳密な剛体挙動を扱わない
- 元になったObsidianノートはこのリポジトリに含まれない
